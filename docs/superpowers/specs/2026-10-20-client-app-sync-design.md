# Client app sync — plugin design

Date: 2026-10-20
Status: agreed, not started

## Goal

Move client communication with JMJ from meetings to async. JMJ follows Projects and Tasks in the Client app ("Suivi de projets", repo `edf-suivi`): he comments, reprioritises, creates Tickets and gives his Answer on Tasks and Projects À valider. I handle almost everything from Obsidian.

This spec covers the vault side. The Client app, its API contract and the milestones are in `edf-suivi/docs/spec.md`; terms are defined in `edf-suivi/GLOSSARY.md`.

## Ownership

- The Client app is the source of truth for **shared fields**. The vault mirrors them and keeps everything else private.
- The plugin talks to the app through a `Remote` interface (below), configured with the app URL and a personal API token in plugin settings. `data.json` is git-ignored by both the vault and this repo.
- The sync truth lives in the app (`edf-suivi/docs/adr/0006-client-app-holds-the-sync-truth.md`): the ids are in the notes, and each Item's **base** (its shared fields and note path as the vault last agreed with the app, in the vault's form) is stored by the app as the plugin sends it. `data.json` holds only the settings, the URL and the token; a `sync` key left by an older version is dropped on load. Any copy of the vault, on any computer, works against the same state once its notes are synced.

## What is shared

Never shared: time logs (`project` blocks), billing, quotes, commands, knowledge, people.

### Projects

- Every project in `2.projects/`, unless frontmatter has `prive: true`.
- Shared fields: title, the `# Description` section, `status:`, `priority:`, `due_date:`.
- `due_date:` frontmatter: the Échéance, the day JMJ needs the Project done, ISO `YYYY-MM-DD`. Absent or empty = none. Any other value (`fin janvier`, `2027-02-30`) makes the Push skip that Project with a Notice naming the note, as an unknown status does. Only Projects have one. The kanban doesn't show it. A base from before the Échéance has no `due_date` and reads as none.
- `status:` frontmatter (new): `À faire` / `En cours` / `En pause` / `À valider` / `Terminé`. `archived: true` = `Terminé`. Independent of priority.
- Identity: `suivi_id:` frontmatter, generated by the plugin and written before the first Push sends the Project.

### Tasks

The line and its indented body are shared: the body (lines after the Task line with an indent above zero, blank lines included while the next non-blank line is indented) becomes the Task's Description, de-indented and shared through `shareBody` (`src/sync/sharedBody.ts`): `![[image]]` embeds uploaded and rewritten, other embeds and `[[wikilinks]]` to plain text, code kept as written. A Loom or Cap URL alone on a body line plays as a Video in the app. `#private` on the line hides the Task and its body.

**Tag tasks** — any line starting with a type tag, in any file, unless it carries `#private`. Project comes from the file (project file, or `project:` frontmatter of a meeting note); none = standalone Task.

| Tag | Client label |
|---|---|
| `#task` | Tâche |
| `#bug` | Bug |
| `#quick` | Rapide |
| `#wait` | En attente (my title says what I'm waiting for) |

`#ask` and `#project` are removed.

**Project steps** — top-level `- [ ]` lines under the `Tasks` heading (existing `findTasksHeadingSection` logic, unchanged; rename the one `# Tâches` heading). A step is a flag on the Task, not a type: it carries a type tag first, then the status token, like a Tag task (`- [ ] #bug p2 Title ^id`); no tag = `task`. The Client recognises a step by its Project badge and the "x/y étapes" count. Steps inherit the Project's priority unless they carry a token (an Override). A `#wait` step shows in En attente like a `#wait` Tag task.

**Status token** — first word after the marker, lowercase only, whole word:

```
#task p2 Nouveau widget saison ^t7f3a
- [ ] p1 fix the x axis of the heatmap ^t91c2
- [ ] #bug p2 Legend overlaps the curve ^t5d10
- [ ] pr Export CSV ^t04be
```

| Token | Status |
|---|---|
| `p0` | En cours |
| `p1`–`p5` | À faire, at that priority |
| `pr` | À valider |
| `#done <date>` / `[x]` | Terminé (a done Project step carries its date after its type tag: `- [x] #bug 2026-10-24 Export Excel ^ab12c`) |
| (none, Project step) | À faire, inherits Project priority |

`À trier` exists only in the app and in the Obsidian Inbox, never in the vault.

**Stable IDs** — `^<id>` block ID at the end of the line (5 characters of `a-z0-9`, the app's format), stripped from the title by the parser. The plugin generates it and writes it into the line before the Push sends the create; Triage keeps the Ticket's app id. A line ending with another block ID (`^abc123` from "copy link to block") is not pushed until it is removed. All write-backs locate the line by ID, not line number. Moving a line between files is a move, not a delete.

## Permissions (enforced by the app)

- **JMJ:** Project and Task priority within P1–P5, a Project's Échéance (set, change, clear; not once Terminé), comments, Tickets (bug / amélioration / idée), the Answer (Validé / À reprendre) on a Task or Project À valider, "Je veux lancer" on an Idea.
- **Me only:** moving anything to or from P0 (JMJ sees P0 but can't set it; for urgency he uses P1 + a comment), status (except through the Answer), titles, moves, deletions.
- JMJ changing the priority of an inheriting Project step makes the Pull write an Override token on the line.
- The Pull writes the Answer back: Validé makes a Tag task `#done <date>`, ticks a Project step with the date of the Answer and sets `archived: true` on a Project; À reprendre gives a Task the `p0` token and a Project `status: en cours`. When I changed that status in the vault too since the base, it becomes a conflict.
- Every Client change lands in my Inbox.

## Push and Pull

- **Pull:** on startup, every 5 min, on command. It fetches every Item's state (`GET /api/state`: current fields, base, archived, the Answer its status comes from) and compares it with the vault; there is no cursor. Only the fields the site can change are pulled: the priority, a Project's `due_date` and an Answer's effects (status, priority, done date). A pulled Échéance is written as `due_date:`, or the key removed when JMJ cleared it. For each, with vault, app and base: vault = app, nothing to do (the base is aligned); app changed, vault = base, the Pull writes the app's value into the vault; vault changed, app = base, the Push offers it; all three differ, a **conflict**. What it wrote, and aligned bases, are acknowledged in one call (`POST /api/state/acknowledge`). A note that can't be read is left alone.
- **Conflicts** are worked out at each Pull, never stored, and shown in the Inbox's Conflits and in the Push review: one button per value, `[ P0 (moi) ]  [ P1 (jmj) ]` (an Answer's status, priority and done date as one unit). An Échéance conflict reads « Échéance changée dans le coffre et dans l'app », its buttons the dates (« 1 mars 2027 ») or « Aucune » for none. Each acts at once: (moi) pushes that field with the app value it expects, (jmj) writes the app's value into the vault; either way the base takes it.
- **Push:** on demand only (meeting Tasks get reorganised before sending). It reads the app's state, then opens a modal titled with the app's host listing what the vault changed against the base, grouped *new / restored / changed (old → new) / conflicts / not pushed (fix in the note)*, one checkbox each, ticked by default; `due_date` shows as the ISO day or « (none) ». A vault id the app doesn't know is a create keeping that id; one it holds archived is « Restaurer »; one it holds as the other kind is an error. Each change carries its base and the app values it expects for the fields it sends; the app refuses a change whose expected values no longer hold, and the next Pull settles it. Unpushed items do not exist for JMJ.
- **Removing** an Item from the app is never a Push: an app Item that no readable note carries is an **Unplaced item**, in the Inbox's « Hors du vault » (below).
- **First Push** (the app holds no base for this vault): open items + items done in the last 30 days. Older history and archived Projects stay vault-only. Never-pushed done lines without a date are in a collapsed group « Terminées sans date », unticked at a first Push, ticked afterwards; pushing one writes today's date into its line.
- **Images**: each `![[image]]` of a body is uploaded at every Push that sends the body; the app recognises content it already has and returns its existing URL.

## Inbox (Obsidian view)

One panel, reload icon at the top:

- **À trier**, pinned on top: new bug / amélioration Tickets and Ideas JMJ launched. **Insérer ici** writes the Task at the cursor (type and priority picked in a dialog): a Tag task `#<type> p<n> <title> ^<id>`, or, when the cursor is on a Project note's Tasks heading or in its section, a Project step `- [ ] #<type> p<n> <title> ^<id>` whose priority defaults to "hériter du projet" (no token). The Ticket's Description goes under the line as its body, indented with one tab, blank lines kept. Images JMJ pasted are downloaded with the token into the note's attachment folder and embedded as `![[…]]`; a later Push uploads them again and the app answers with the URL it already has. An image that can't be downloaded keeps its app link, with a notice. The line and body are sent to the app as the Item's base (`POST /api/state/acknowledge`), so the next Push shows no change. **Nouveau projet** creates a Project file from the template with its `suivi_id:`. The app item stays the same, so JMJ's description and comments stay attached.
- **Hors du vault**: Unplaced items, i.e. non-archived, triaged or pushed app Projects and Tasks that no readable note carries (Tickets and Ideas not yet triaged excluded). **Insérer ici** places it as Triage does, keeping its id (a Project's note gets its `due_date:` when it has one), and sends its base; **Retirer de l'app** archives it. From 5 of them, one entry « n éléments hors du vault » opens a modal with a « Retirer » switch per Item and one for all.
- **Conflits**, while the last Pull found some; each button settles one at once (above).
- Then the Client's unread entries; « Lu » or opening one takes it out. Empty, the Inbox says « Rien à traiter ».
- **The Activity**, a toggle in the pane header (`GET /api/activity`): every event of the log, newest first, grouped by day, the events of my own Pushes collapsed to one line per Push ("Push : 12 changements"). Filter Tous / JMJ / Moi. Comment entries show the full body rendered as markdown, known `@handle`s highlighted; a comment that mentions me (`@baptiste`) stands out. Clicking an entry opens the file at the line and, for comments, the thread panel. The last 30 days are loaded; "Charger plus" pages further back.
- **Read rule**: an entry is unread when JMJ wrote it and I haven't marked it read; my own site actions and Push lines never are. "Lu" or opening an entry marks it read, "Tout marquer comme lu" every Client event up to the newest loaded. In the Activity, read entries are dimmed.

Signals, from the loaded entries:

- after each Pull the Inbox reloads, and each Client entry newer than its previous load gets a toast ("JMJ a commenté Algo détection", "P1 → P2 sur Prix SPOTS", "Échéance repoussée au 1 mars 2027 sur Prix SPOTS", the app's label); none at startup;
- a status bar item with the unread count, opening the Inbox;
- on kanban cards with unread entries, a badge at the top right ("💬 2 · P1→P2", "📅 1 mars 2027" or "📅 retirée" for the newest Échéance change) and a tinted background; clicking the badge opens the Inbox filtered to that item ("<titre> ✕" clears the filter).

New Ideas do not reach À trier: they stay in the app's Idées list until JMJ launches one.

## Other plugin changes

- **Comment side panel:** thread of the Task/Project under the cursor (on its line or in its body), reply, edit or delete own comments from there. Comments are never written into markdown.
- **Kanban:** `À valider` column (`pr`), the unread badge above, one colour per type (bug red `#b82626`, quick yellow `#f7d522`, task grey, wait faded and dashed) as the card border, a small label in that colour before the title ("BUG", "RAPIDE", "ATTENTE"; none for task) and a dot of that colour in front of each step line on a Project card, Overridden Project steps greyed on their Project card and shown as their own card in the right priority column; ticking a step writes today's date after its type tag, unticking removes it.
- **Disconnect** (settings, « Se déconnecter de l'app Client »): after a confirmation giving the real counts and URL, removes the app-format ids from the notes (`suivi_id:`, `^id`) and clears the URL and token. It never calls the app, which keeps everything; reconnecting the vault to it would create every Item again.
- **Parser:** `quick` stays, `project` type removed, token matched as lowercase whole first word (today `/p\d/i` matches anywhere, e.g. `Étape2`), block ID stripped from title, writes by ID instead of line number (today `updateTaskTag` overwrites `lines[task.line]` blindly).

## Remote interface

```ts
interface Remote {
	push(changes: PushChange[]): Promise<PushResult[]>;
	state(): Promise<ItemState[]>; // every Item with its base, archived ones included
	acknowledge(items: AcknowledgedItem[]): Promise<void>; // set bases the vault now agrees on
	comments(itemId: string): Promise<Comment[]>;
	comment(itemId: string, body: string): Promise<Comment>;
	editComment(commentId: string, body: string | null): Promise<void>; // null = delete
	inbox(): Promise<InboxResponse>; // items À trier
	activity(before?: number, days?: number): Promise<ActivityResponse>; // a page of the feed
	markRead(eventIds: number[]): Promise<void>;
	markReadUpTo(id: number): Promise<void>; // every Client event up to id
	upload(data: ArrayBuffer, name: string): Promise<string>; // returns URL (the existing one for known content)
	image(path: string): Promise<{ data: ArrayBuffer; type: string }>;
	triage(itemId: string, as: TriageRequest): Promise<TriageResponse>;
}
```

The only implementation is the `edf-suivi` HTTP API; types are copied from `edf-suivi` (it owns the contract). Parser, kanban, Inbox and Push screen depend only on this interface.
